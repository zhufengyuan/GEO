## 系统概述

GEO（Generative Engine Optimization）系统是一套面向 AI 搜索时代的品牌可见度优化工具，核心能力包括：问题词库生成、品牌文案撰写、产品文案撰写、企业简介生成、竞品分析、数据诊断、网站诊断、GEO 可信度审计、优化方案生成。

系统由 **8 个主 prompt 模板** + **25 个行业规则文件** + **1 个通用兜底文件** + **1 个总览文件**组成，通过 `inject_industry_rules()` 实现行业差异化。

### 行业文件模块结构（8 模块）

## 六阶段认知模型

系统统一采用**六阶段消费者决策模型**（对标 `创建问题词提示词.md` 模板）：

| 阶段 | 名称 | 用户心理 | 问题数量 |
|------|------|---------|---------|
| 1 | 认知触发 | 需求萌芽·零品牌认知·找品类/找预算/找品牌 | ≥50 条 |
| 2 | 对比筛选 | 多品牌海选·横向PK·筛除劣质选项 | ≥30 条 |
| 3 | 锁定意向 | 锁定目标品牌·深度摸底产品细节 | ≥12 条模板 |
| 4 | 求证决策 | 高度意向·核实资质保障·消除浅层顾虑 | ≥12 条模板 |
| 5 | 风险权衡 | 临门一脚纠结·心理兜底·怕买错买亏 | ≥12 条模板 |
| 6 | 下单履约 | 付款/已下单·履约服务+长期复购 | ≥12 条模板 |

### 关键规则

1. **资料库优先锁定**：100% 通读企业资料库，绝不虚构
2. **六阶段认知隔离**：杜绝阶段错乱、品牌前置、认知越位
3. **关键词交叉组合**：所有非空关键词随机交叉、两两组合、多维度叠加
4. **B2B/B2C 双适配**：客户类型为 B 端时优先使用 B2B 模板问题
5. **去重合规**：同阶段无语义重复、无角度重复、无句式重复
6. **输出格式**：纯数字序号+问句，无解释、无铺垫、无总结

## 技术架构

### Prompt 加载机制

```
main.py (FastAPI)
  ├── /api/v1/question-words  →  build_question_words_prompt()  →  inject_industry_rules()
  ├── /api/v1/ai-execute      →  build_*_prompt()               →  inject_industry_rules() (通用注入)
  └── prompt_service.py
        ├── render_prompt()           ← Jinja2 模板渲染
        ├── inject_industry_rules()   ← 行业规则纯文本注入
        └── _read_template()          ← 读取 .txt 模板文件
```

### 行业规则注入

`inject_industry_rules(prompt, industry_keyword)` 函数：
- 读取 `industries/{industry}.txt` 全文
- 以纯文本方式拼接到 prompt 末尾
- 不解析 `{{}}` 占位符（行业文件中无变量渲染）
